# cf_maker_new

Утилита для построения и фита 3D корреляционных функций (HBT) с использованием ROOT.

Проект предназначен для batch-обработки больших ROOT-файлов и сохранения результатов
в виде отдельных выходных файлов.

---

# Структура

```
src/
├── main.cpp            — точка входа
├── config/             — загрузка и валидация JSON-конфигурации
├── core/               — общие примитивы: бининг, LCMS-оси, утилиты файловой системы
├── io/                 — чтение входных гистограмм
├── fit/                — модель фита, FitResult, начальные параметры
├── draw/               — отрисовка и стилизация
└── analysis/           — стадии анализа: 3D CF, 1D/2D проекции, отношения, зависимости
```

# Установка зависимостей

Общие зависимости: C++17 компилятор, CMake ≥ 3.20, git, **ROOT 6**,
OpenSSL (headers), опционально ccache / clang-format / clang-tidy.

```bash
git submodule update --init --recursive
```

# Сборка

Из корня проекта:

```bash
make
make test
make run CONFIG=config/kt.json
```

`Makefile` по умолчанию выбирает `g++`, Release и два процесса компиляции.
Перед сборкой он повторяет конфигурацию CMake, восстанавливая отсутствующие
сгенерированные файлы. Компилятор задаётся явно через `make CXX=clang++`;
переменная `CXX` из окружения не подменяет Linux-компилятор на `clang-cl`.

Полезные команды и настройки:

```bash
make help
make check CONFIG=config/kt.json        # сборка → тесты → анализ
make rebuild JOBS=4                     # пересобрать с очисткой объектов
make doctor                            # версии компилятора, CMake, ROOT
make demo                              # полный запуск на Gaussian-входе
make test CTEST_ARGS="-R ratios"        # один тест
make format-check                      # проверить форматирование
make lint                              # clang-tidy
make sanitize-test                     # ASan/UBSan приложения и всех тестов
```

Дополнительно: `BUILD_DIR`, `BUILD_TYPE`, `ROOT_DIR`, `CMAKE_ARGS`,
`SANITIZE_BUILD_DIR`, `FIXTURE_DIR`, `CLANG_FORMAT`, `CLANG_TIDY` и
`CLANG_TIDY_ARGS`. Sanitizer-сборка использует игнорируемый `build-sanitize/`.
ROOT должен быть установлен и доступен в текущем окружении.

Для прямой сборки через CMake:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
```

После сборки исполняемый файл `main` будет находиться в директории `build/`.

# Текст диплома и презентация

Текст диплома и презентация находятся в [docs/thesis](docs/thesis/README.md).
Чтобы выполнить анализ и сразу получить презентацию с его результатами,
из корня репозитория запустите:

```bash
make run-presentation CONFIG=config/kt.json
# или для зависимости по быстроте:
make run-presentation CONFIG=config/y.json
```

На Linux x86_64 и ARM64 команда использует готовый сборщик презентации из
репозитория; Go для запуска не нужен. Команда проверяет инструменты LaTeX,
собирает программу, выполняет анализ,
добавляет в презентацию главу с параметрами запуска и созданными графиками,
затем записывает **`presentation.pdf` в директорию результатов расчёта**.
Копия также находится в `docs/thesis/build/presentation/presentation.pdf`.

Если расчёт уже выполнен, повторная сборка PDF не запускает его заново:

```bash
make presentation CONFIG=config/kt.json
make presentation RESULTS=/path/to/results
make presentation CONFIG=config/kt.json PRESENTATION_PLOTS=0  # все графики
```

`RESULTS` выбирает готовый расчёт напрямую; относительные пути `CONFIG` и `RESULTS`
считаются от корня репозитория. Для включения графиков нужны `images.need: true`
и формат `pdf`, `png`, `jpg` или `jpeg` в конфиге. По умолчанию включается не более 12
графиков; `PRESENTATION_PLOTS=0` добавляет все. Старые рисунки событий, частиц и
инвариантного радиуса текущая программа не создаёт; их отсутствие в исходной
презентации описано в README документов.

Если программа завершилась кодом `2`, `run-presentation` собирает диагностический
PDF с явной отметкой о непригодных фитах. Это не делает расчёт успешным;
обычные `make run` и `make check` сохраняют код ошибки. При фатальной ошибке
программы сборка PDF останавливается.

Документы можно собирать отдельно от приложения:

```bash
make docs          # оба PDF
make thesis        # только текст
make presentation  # презентация и результаты выбранного расчёта
```

Результаты: `docs/thesis/build/report/thesis.pdf` и
`docs/thesis/build/presentation/presentation.pdf`. Зависимости LaTeX,
необязательная пересборка сборщика, недостающие исходные рисунки и строгая
сборка описаны в README документов.
Если выбранного расчёта ещё нет, `make presentation` собирает исходные слайды
и сообщает, что глава с результатами не добавлена.
Результаты старой версии без `run_manifest.json` нужно получить повторным
запуском обновлённой программы. При явном `RESULTS` отсутствие manifest — ошибка.
При `images.need: false` PDF содержит параметры и статус текущего расчёта,
а также пояснение, что рисунки не экспортировались. Это настройка по умолчанию
у Gaussian-генератора; для графиков её нужно изменить и повторить расчёт.

# Запуск

Программа принимает один аргумент — путь к JSON-конфигурации:

```bash
./build/main config/kt.json
```

Запускать нужно из корня репозитория. Результат работы будет находиться в директории
`<base_output>/<dir>` из конфигурации.

Коды завершения: `0` — успешный запуск, `1` — ошибка конфигурации или ввода/вывода,
`2` — хотя бы один выбранный фит отсутствует или непригоден для анализа при
запуске `cf3d`, `dependency` или `projections_1d`. Диагностика таких фитов сохраняется.

# Входные данные и ошибки CF

Принимаются гистограммы `TH3F` и `TH3D` с осями out/side/long:
`bp_CH_CENT_num_BIN` содержит число реальных пар N,
`bp_CH_CENT_num_wei_BIN` — сумму их весов S. CF равна S/N.

По умолчанию используется статистика весов одних и тех же пар, как в `sthbtmaker`.
Числитель должен хранить `Sumw2` с Q = Σw², знаменатель — ошибки √N.
При N > 1 квадрат ошибки среднего оценивается как
`(Q - S²/N) / (N(N - 1))`. При N ≤ 1 или нулевой дисперсии ошибка равна нулю;
такие бины ROOT исключает из χ²-фита. Эта оценка предполагает независимость пар
и не учитывает ковариации от общих событий и треков.

Допуск проверки Q ≥ S²/N учитывает точность исходного накопления и число пар.
После преобразования `TH3F` в `TH3D` сохраняется признак исходной точности,
в том числе в 1D/2D-проекциях. Если дисперсия неразличима на фоне округления,
сохраняется измеренное S/N с ошибкой 0: такой бин исключён из обычного χ²-фита,
но остаётся в проекции данных. Это обрабатывает и отрицательные, и ложные
положительные остатки возле нуля. Для `TH3F` число таких бинов выводится в лог.
Округление `TH3F` само по себе больше не останавливает запуск до рисования.

Несогласованные оси, отсутствующий Sumw2, неверные счётчики и моменты,
невозможные даже с учётом округления, вызывают ошибку. Для новых данных
производителю предпочтительно записывать `TH3D`: конверсия уже накопленных
данных не восстанавливает потерянную точность. Оценка округления предполагает
заполнение весами и сложение гистограмм, как в `sthbtmaker`; произвольно
изменённые вручную моменты этим контрактом не описываются.

Проблемный бин можно прочитать напрямую, без конверсии и изменения файла:

```bash
root -l -b -q 'tools/inspect_pair_moments.C("input.root", "bp_0_2_num_wei_0", 1386)'
```

# Генератор тестовых данных

```bash
./build/generate_gaussian input/gaussian
./build/main input/gaussian/config.json
```

Генератор создаёт `input.root` и готовый `config.json` в указанной директории.
Существующие файлы не перезаписываются. Все зарядовые группы, центральности и
бины получают одинаковую гауссову корреляционную функцию:

```text
C(q) = 1 + lambda * exp(-(R_out²*q_out² + R_side²*q_side² + R_long²*q_long²) / 0.197²)
```

Радиусы задаются в фм, q — в ГэВ/c. Cross-термы равны нулю.
Имена гистограмм совместимы с анализом: `bp_CH_CENT_num_BIN` — постоянный
знаменатель, `bp_CH_CENT_num_wei_BIN` — числитель `den * C(q)`.
Значения вычисляются в центрах бинов. Параметры генерации записываются
в объект `generator_truth` внутри ROOT-файла.

```bash
./build/generate_gaussian input/gaussian_noisy --type rapidity \
    --r-out 4 --r-side 5 --r-long 6 --lambda 0.7 \
    --bins 40 --q-max 0.3 --counts 10000 --noise --seed 42
```

По умолчанию используется `kt`, радиусы 4/5/6 фм, λ=0.7, сетка 40³
в диапазоне ±0.3 ГэВ/c и знаменатель 10000 на бин. Без `--noise` CF точная;
с `--noise` числитель получает пуассоновские флуктуации с заданным seed.
Знаменатель фиксирован, его ошибка нулевая; ошибка числителя равна √num.
Генератор записывает маркер `TNamed("correlation_statistics", "fixed_reference")`;
анализ использует ошибку `σC = σS/N`. Нулевые ошибки знаменателя сами по себе
не выбирают этот режим: маркер нужен для явного указания модели статистики.
Это искусственные данные для проверки фита и пайплайна.

Генерируемый конфиг запускает все стадии в одном потоке без сохранения картинок;
результаты попадают в `<директория>/results`. Полный список опций:
`./build/generate_gaussian --help`.

# Конфигурация

Все секции, кроме `machine` и `vars`, опциональны — у них есть дефолты в коде,
поэтому минимальный конфиг выглядит так:

```json
{
    "machine": { "base_input": "/data", "base_output": "/results" },
    "vars": {
        "input": { "file": "merged.root", "type": "kt" },
        "output": { "dir": "run1" }
    }
}
```

Полный пример — `config/kt.json`. Секции:

| Секция | Что настраивает |
|---|---|
| `machine` | корневые пути машины (`base_input` + `vars.input.file`, `base_output` + `vars.output.dir`) |
| `vars` | входной файл и тип анализа (`kt` / `rapidity`) |
| `fit` | `q_max` — диапазон фита по q; `use_default_ip` — дефолтные начальные параметры вместо табличных; `options` — опции ROOT `Fit()` (внимание: `M` принудительно включает TMinuit+MigradImproved, для Minuit2 не указывайте `M`); `minimizer` — `Minuit`/`Minuit2` (по умолчанию `Minuit2`); `retry_with_defaults` — при плохом фите перефит с дефолтными начальными параметрами (лучший по chi2); `use_integral` — среднее функции по объёму бина вместо значения в центре (опция `I`); `minos_errors` — Minos-ошибки (опция `E`, медленно); `limits` — лимиты параметров (`radius_sq`, `cross`, `lambda` — пары `[min, max]`); `freeze` — зафиксированные параметры: `{"r_os": 0.0, ...}` (значение — фикс; `r_out`/`r_side`/`r_long` задаются в фм, остальные как в параметризации; отсутствующий ключ = свободен). Секция `freeze` при наличии заменяет дефолт целиком: `"freeze": {}` освобождает cross-термы |
| `projections` | ширины срезов: `slice_1d`, `slice_2d` (freeze), `crop_2d`, `slice_ratio`, `fit_over_cf_range`; диапазоны осей 1D-канвасов: `axis_range_1d` (± по q), `cf_y_range_1d`, `fit_over_cf_y_range_1d` (пары `[min, max]`) |
| `binning` | **необязательно**: свои границы `values` (edges) + `names` (на каждый бин, т.е. `values.size() - 1`), опционально `file_names` для имён файлов. Если секции нет — встроенные таблицы kt/rapidity |
| `images` | `need: false` — не сохранять картинки (batch); `format` — `pdf`/`png`/... |
| `stages` | вкл/выкл стадии пайплайна: `cf3d`, `dependency`, `projections_1d`, `projections_2d`, `ratios`. При `cf3d: false` стадии `dependency`, `projections_1d` и `ratios` требуют совместимого сохранённого `cf3d.root` с метаданными фитов |
| `selection` | `charges: [0, 1]`, `centralities: [0, 1, 2, 3]` — подмножество для быстрых прогонов |
| `logging` | `level`: `debug`/`info`/`warning`/`error`; `file`: имя лог-файла в выходной директории (пустая строка — только stderr) |
| `threads` | число потоков для параллельного фитирования, `0` — автоматически (`hardware_concurrency`). `Minuit2` поддерживает параллельную обработку; для `Minuit` или опции `M` программа принудительно использует один поток и сообщает об этом в логе |

Неизвестные ключи отклоняются с ошибкой, неверные значения валидируются
(например, `binning.names` должно содержать `values.size() - 1` элементов).

При каждом запуске в выходную директорию пишется снапшот эффективного конфига —
`run_config.json` (со всеми дефолтами и полными путями), чтобы всегда было видно,
чем именно получены результаты.

`cf3d.root` сохраняет полный `FitResult`: параметры, ошибки, статусы, χ²/ndf,
p-value, признаки достижения лимитов, число попыток и матрицу корреляций.
После обычного χ²-фита программа сама суммирует
`χ² = Σ[(C_i − f_i) / σ_i]²` по выбранным бинам и вычисляет
`ndf = N_бинов − N_свободных_параметров`. При стандартных опциях `RQS0`
бины с нулевой ошибкой исключаются, а фиксированные параметры не уменьшают ndf.
При `use_integral` или опции `I` значение `f_i` усредняется по объёму бина.
P-value — верхний хвост распределения χ²: `Q(ndf/2, χ²/2)`, вычисленный через
`ROOT::Math::chisquared_cdf_c`. Значения сохраняются в `FitResult` и выводятся
при `logging.level: "debug"`. Для likelihood (`L`), Pearson (`P`),
пользовательской функции (`U`) и масштабирования `WIDTH` сохраняется статистика ROOT.
При продолжении запуска проверяются SHA-256 исходного файла, модель статистики,
параметры фита, выборка зарядов/центральностей и бининг. Старые файлы без полных
метаданных нужно пересоздать с `stages.cf3d: true`.
Графики параметров и проекции модели используют только успешные фиты с конечными
значениями, ndf > 0 и без достижения лимитов; остальные результаты отмечаются
как непригодные.

Срезы проекций суммируют полные бины, пересекающие интервал `[-slice, +slice]`.
Бин, который только касается границы среза, не включается. Границы,
отличающиеся от края бина на несколько единиц округления `double`, считаются
совпадающими; выбор бинов не зависит от округления в `TAxis::SetRangeUser`.
Ширина среза должна быть конечной и положительной.
Срез, выбирающий только underflow на смещённой оси, отклоняется: ROOT при такой
проекции ошибочно суммирует обычные бины.

Стадия `ratios` требует оба заряда: `selection.charges: [0, 1]`.
`ratio_proj` — отношение CF, каждая из которых получена как ΣS/ΣN по срезу
исходных гистограмм; пары задают веса ячеек. `proj_of_ratios` — отдельная
величина: невзвешенное среднее C++/C-- по ячейкам с парами обоих зарядов
и ненулевым C--. Нулевой C++ учитывается. Исходный ROOT-файл нужен для обеих
операций; отсутствие необходимых гистограмм вызывает ошибку.

# Тесты

```bash
ctest --test-dir build --output-on-failure
```

Регрессии проверяют чтение `TH3F`/`TH3D`, ошибки среднего веса и фиксированного
знаменателя, ориентацию 2D-проекций на некубической сетке, выбор бинов среза
при округлении границ, нормировку отношений и разную заполненность ячеек,
ручной пересчёт χ², ndf и p-value, фильтрацию плохих фитов, сериализацию
и проверку совместимости сохранённых результатов, последовательный Minuit
и параллельный Minuit2. Генерируемые данные также проходят полный пайплайн.

# Тулчейн

  ```bash
  clang-format -i $(find src tests -name '*.cpp' -o -name '*.h')
  ```

  Linux:

  ```bash
  clang-tidy -p build $(find src -name '*.cpp')
  ```

  macOS (keg-only `llvm` + `-isysroot`, подробнее в AGENTS.md):

  ```bash
  /opt/homebrew/opt/llvm/bin/clang-tidy -p build \
      --extra-arg="-isysroot" --extra-arg="$(xcrun --show-sdk-path)" \
      $(find src -name '*.cpp')
  ```

- **Sanitizers** — `cmake -S . -B build-asan -DCF_MAKER_SANITIZE=ON`
