## Сборка из корня репозитория

Полный путь от расчёта до готовой презентации выполняет одна команда:

```bash
make run-presentation CONFIG=config/kt.json
make run-presentation CONFIG=config/y.json
```

Она проверяет зависимости документов до анализа, собирает приложение, запускает
выбранный конфиг и добавляет в презентацию главу «Результаты текущего расчёта».
Готовый **`presentation.pdf` находится рядом с ROOT-файлами в выходной директории
расчёта**. Второй экземпляр сохраняется в `docs/thesis/build/presentation/`.

Чтобы обновить только PDF по уже готовым результатам:

```bash
make presentation CONFIG=config/kt.json
make presentation RESULTS=/path/to/results
make presentation CONFIG=config/y.json PRESENTATION_PLOTS=0  # все графики
```

По умолчанию используется `CONFIG=config/kt.json`. `RESULTS` выбирает директорию
готового расчёта напрямую и имеет приоритет над `CONFIG`. Пути относительно
корня репозитория работают также при вызове `make` внутри `docs/thesis`.
`run-presentation` всегда использует результаты только что запущенного `CONFIG`.
По умолчанию в PDF добавляется не более 12 графиков; число задаёт
`PRESENTATION_PLOTS`. Значение `0` включает весь набор, что для большого расчёта
может дать много дополнительных слайдов.

В главу входят параметры запуска, зависимости радиусов и λ, диагностика качества
фитов, 1D-проекции out/side/long и 2D-проекции out-long, если соответствующие
стадии создали изображения. Для графиков в конфиге укажите:

```json
"images": { "need": true, "format": "pdf" }
```

Также поддерживаются `png`, `jpg` и `jpeg`. Копирование и включение рисунков
выполняются автоматически; их не нужно вручную переносить в `presentation/fig/`.
`cf3d` и `ratios` сейчас сохраняют результаты в ROOT, поэтому отдельные картинки
для этих стадий в PDF не добавляются.
При `images.need: false` вместо графиков добавляются параметры и статус расчёта
и слайд с пояснением об отсутствии экспорта. Gaussian-генератор по умолчанию
отключает картинки: для презентации с графиками измените эту настройку в его
конфиге и повторите анализ.

Код `2` приложения означает непригодные выбранные фиты. `run-presentation`
в этом случае продолжает сборку **диагностического PDF** с явным предупреждением
о состоянии расчёта. Обычные цели `run` и `check` сохраняют код ошибки `2`.
При фатальном сбое расчёта презентация автоматически не публикуется.
Если директории результатов ещё нет, `make presentation` собирает исходные
слайды без главы результатов и сообщает об этом. Подключение прошлого расчёта
удаляется перед подготовкой новой презентации.

Актуальность результатов проверяется по `run_manifest.json`: программа записывает
состояние `running` до изменения выходных файлов и `completed` или `incomplete`
после завершения. В слайды попадают только графики, указанные в manifest текущего
запуска. Состояние `running` не допускает публикации; код `1` при запуске через
`run-presentation` останавливает команду. Старые результаты без manifest при
автоматическом выборе через `CONFIG` не включаются: будет собрана исходная
презентация с сообщением о необходимости повторить анализ обновлённой программой.
При явном `RESULTS` отсутствие manifest считается ошибкой.

Подготовка создаёт в каталоге сборки `presentation-results.json` с выбранным
расчётом и снимок используемых изображений в `current-results/`. После успешной
сборки LaTeX PDF копируется в директорию именно этого расчёта.

Остальные цели документов:

```bash
make docs          # текст работы и презентация
make thesis        # только текст работы
make presentation  # презентация с результатами выбранного расчёта
make docs-clean    # очистить результаты сборки документов
```

Готовые файлы:

- `docs/thesis/build/report/thesis.pdf`
- `docs/thesis/build/presentation/presentation.pdf`

Цели `docs`, `thesis` и `presentation` не требуют ROOT, CMake или компиляции
программы. `run-presentation` требует также зависимости приложения.
Для другого каталога сборки документов задайте `DOCS_BUILD_DIR`, для другого
latexmk — `LATEXMK`, для другого Python — `PYTHON`:

```bash
make docs DOCS_BUILD_DIR=/tmp/cf-maker-docs LATEXMK=/path/to/latexmk PYTHON=python3
```

Можно также собирать внутри директории материалов:

```bash
make -C docs/thesis
make -C docs/thesis report
make -C docs/thesis presentation
make -C docs/thesis presentation RESULTS=/path/to/results
make -C docs/thesis doctor
make -C docs/thesis clean
```

Здесь каталог результатов задаётся переменной `BUILD_DIR`, по умолчанию `build`.
Сборка выполняется через `latexmk -xelatex`; latexmk запускает Biber автоматически
для библиографии и повторяет TeX-проходы до разрешения ссылок.
Для строгой проверки используется штатная опция `-usepretex`;
её описание приведено в [руководстве latexmk](https://www.cantab.net/users/johncollins/latexmk/latexmk-488.pdf).

## Зависимости

Нужны XeLaTeX, latexmk и Biber; для автоматической главы результатов — Python 3
без дополнительных библиотек. Набор пакетов для Ubuntu:

```bash
sudo apt-get update
sudo apt-get install python3 latexmk biber texlive-xetex texlive-latex-extra \
  texlive-bibtex-extra texlive-lang-cyrillic texlive-science \
  fonts-freefont-otf texlive-fonts-extra-links
```

Альтернатива — полный набор TeX Live:

```bash
sudo apt install python3 texlive-full latexmk biber fonts-freefont-otf
```

Документы используют кириллицу, `polyglossia`, `fontspec`, `biblatex-gost`,
`algorithm2e`, а презентация — тему Metropolis. В macOS подходит установленный
MacTeX с `latexmk`, XeLaTeX и Biber в `PATH`.

`texlive-science` нужен для `algorithm2e` в тексте работы;
`texlive-fonts-extra-links` обеспечивает поиск файлов FreeFont из TeX.
Для этих документов весь пакет `texlive-fonts-extra` не требуется.

Библиография презентации подключается через `\input`, поэтому её сборка
в отдельный каталог не требует подкаталога `templates/` для служебных файлов.
Это устраняет ошибку записи `templates/bib-page.aux` с latexmk 4.83.
6 октября исправление проверено на TeX Live 2026 прямым запуском XeLaTeX
и полной сборкой презентации с пустым каталогом результатов.
Все 12 начертаний FreeFont проверены отдельно на латинице и кириллице.

Эта копия проверена 5 октября 2026 г. на XeLaTeX из TeX Live 2026,
latexmk 4.88 и Biber 2.22: текст работы собран на 15 страницах,
презентация — на 42 страницах PDF. Глава «Статистика корреляционной функции»
содержит восемь слайдов на страницах 18–25 PDF: средний вес, биномиальная модель,
ковариация, применимость ROOT `B`, контрольный пример и ограничения оценок ошибок.
За ней расположен раздел о точности гистограмм, проекциях,
контроле аппроксимации и проверках программы.
Строгий режим отдельно проверен для обоих документов.
Это число страниц исходной презентации; автоматическая глава расчёта добавляет
страницы в зависимости от набора выбранных графиков.

Автоматическая цепочка проверена на синтетическом Gaussian-примере: анализ,
экспорт графиков и сборка PDF выполняются одной командой. Проверены повторная
сборка без анализа, пути с пробелами, диагностический PDF при коде `2` и
исключение старых изображений отключённой стадии. Все 16 проверок CTest прошли,
включая тесты manifest и 16 проверок Python-инструмента.

## Недостающие рисунки

В исходной копии нет 14 рисунков отчёта и 25 рисунков презентации. При обычной
сборке их места занимают явно обозначенные рамки с именами отсутствующих файлов.
Это позволяет проверять текст и обновлённые слайды; рамки не являются данными
анализа. Такой PDF нужно дополнить исходными рисунками перед защитой.

Это исторические ссылки на рисунки событий, частиц, инвариантного радиуса и
старые сводные изображения. Текущий `cf_maker` не создаёт весь этот набор;
автоматическая глава результатов использует только реальные графики выбранного
расчёта и не заменяет ими несопоставимые старые рисунки.

Скопируйте настоящие файлы в `report/images/` и `presentation/fig/`, сохранив
имена из `\includegraphics`. Для проверки полноты материалов включите строгую
сборку:

```bash
make docs STRICT_ASSETS=1
# или из директории материалов:
make -C docs/thesis STRICT_ASSETS=1
```

Она выполняет новый TeX-проход и завершится ошибкой при отсутствии рисунка,
даже если черновой PDF уже собран.
